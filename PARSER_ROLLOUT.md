# Gmail VK parser: проверка и применение на Bothost

## Что изменилось

Старый парсер принимал подпись каждой ссылки /im за текст сообщения и запоминал
последнее имя во всём письме. В одиночном письме подпись ссылки — дата, а текст
лежит в соседней строке таблицы. В сводке каждая карточка имеет своё имя и дату.
Новый парсер учитывает оба реально проверенных шаблона, убирает повторную кнопку
«Ответить» и не переносит имя/время между карточками.

Когда ВК не включил текст, бот сообщает об этом явно. Слово «сообщение» или дата
остаются обычным текстом, если они действительно находятся в поле сообщения.
Время берётся из карточки без пересчёта часового пояса. В text/plain его нет —
поле времени остаётся пустым, дата доставки письма не используется.
Прямая ссылка сохраняет sel/msgid/cmid; переход и выделение сообщения зависят
от клиента ВК. Трекинговые ссылки не открываются и их параметры не пересылаются.

## Защита и ограничения

Обрабатываются письма с единственным ожидаемым From и единственным
Authentication-Results от mx.google.com с DKIM pass для notify.vk.com (или
notify.vk.ru) и соответствующим DMARC pass. Просто подставить From недостаточно.
Доверие к этим заголовкам допустимо только для писем, полученных непосредственно
из Gmail через IMAP TLS; это НЕ самостоятельная проверка подписи произвольного
.eml. Нельзя направлять парсер на сторонний IMAP или загруженные извне файлы и
считать их проверенными. См. [RFC 8601](https://www.rfc-editor.org/rfc/rfc8601.html).

Письма без нужной аутентификации, неизвестные шаблоны и письма более 2 МБ
пропускаются. В текущем цикле IMAP курсор после такого письма продвигается:
это защищает обработку следующих писем, но не даёт автоматического повтора после
добавления поддержки нового шаблона. Отсутствующие в письме текст и медиа
восстановить нельзя. HTML и plain альтернативы не смешиваются; неизвестный HTML
не заменяется догадкой из plain. Сводка только в plain не содержит нужных данных.

## Проверка без запуска бота

```sh
python -m pip install -r requirements.txt
python -m unittest discover -v
```

Тесты используют обезличенные реальные шаблоны, поддельные заголовки,
повреждённые/внешние ссылки, MIME-вложения, base64/quoted-printable, plain,
многострочный текст и SQLite в памяти. Отправка в Telegram заменена заглушкой.
Рабочие токены и Gmail для тестов не нужны. Исходные письма в репозиторий не входят.

## Применение — только после подтверждения владельца

1. Зафиксируйте текущую рабочую ветку/коммит, главный файл и значение DB_FILE.
   Убедитесь, что нет автоматического развёртывания непроверенных веток.
2. В согласованное время остановите единственный экземпляр бота. Сохраните копию
   его SQLite-базы (по умолчанию vk_mail_state.sqlite3) и настроек в приватном
   месте. База содержит last_uid и sent: их нельзя обнулять.
3. Если база лежит вне постоянного хранилища, скопируйте её ПОСЛЕ остановки
   в /app/data/vk_mail_state.sqlite3 и задайте DB_FILE именно этим путём.
   Сначала убедитесь, что перенесён существующий файл, а не создан пустой.
   Bothost описывает сохранение данных в
   [документации хранилища](https://bothost.ru/docs/database-storage).
4. В настройках репозитория Bothost выберите ветку fix/gmail-vk-message-parser
   (либо main после отдельного одобренного слияния). Сохранение настройки может
   запустить деплой: выполняйте этот шаг только после резервной копии.
   См. [выбор ветки](https://bothost.ru/docs/repository-branch-deploy).
5. Явно укажите главный файл gmail_bot.py и Python 3.11. Автовыбор может выбрать
   другой bot.py. См. [главный файл](https://bothost.ru/docs/main-file-entrypoint).
   В сборку должен попасть и новый vk_mail_parser.py. requirements.txt прежний.
   Сохраните токены и остальные переменные; GMAIL_IMAP_HOST — imap.gmail.com.
6. Запустите один экземпляр, проверьте /status и /test, затем дождитесь нового
   письма ВК и сравните имя, текст, время и переход по кнопке с Gmail.
   Старые ошибочные уведомления автоматически заново не отправляются:
   прежние хеши и last_uid сохранены. Не удаляйте базу ради повторной проверки.

## Откат

Остановите обновлённый процесс, верните исходную ветку/коммит и gmail_bot.py,
оставьте ту же актуальную SQLite-базу и DB_FILE, запустите один экземпляр.
Схема базы и формат хешей не изменены. Резервную копию базы восстанавливайте
только при повреждении: откат last_uid может повторить уже отправленные письма.
